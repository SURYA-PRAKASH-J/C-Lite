C-Lite Reference Manual

Version 1.0 • Language Specification and Reference

C-Lite is a small, C-inspired interpreted scripting language written from scratch in C. The language implementation uses a hand-written lexer, a recursive-descent parser, and an Abstract Syntax Tree (AST) tree-walking interpreter.

1. Getting Started

The interpreter takes a source code file (typically with a .cl extension) and walks the generated AST nodes directly. To compile the interpreter, execute the build configuration: 

make

To run a script file, call the interpreter binary: 

./clite script.cl

To output debug traces (lexer tokens, parser steps, and interpreter evaluation logs), pass the --debug command-line argument: 

./clite script.cl --debug

2. Lexical Conventions

Identifiers are sequences of letters, digits, and underscores, starting with a letter or underscore: [a-zA-Z_][a-zA-Z0-9_]*.

Keywords are reserved and cannot be used as identifiers: int, bool, char, str, string, if, else, while, return, true, false, echo, and endl.

Literals represent fixed values. Standard integers, single-quoted characters (e.g., 'a'), and double-quoted strings (e.g., "hello") are parsed as literals. Backslash escape sequences (e.g., \n or \") are not parsed and are read as literal characters.

Comments are single-line, starting with // and ending at the next newline character.

3. Variables and Types

C-Lite is explicitly typed. A variable must be declared with a specific type before it can be updated or used. Variable declaration syntax requires a type name, an identifier, an assignment operator, and an initializing expression. 

int count = 0;
bool isFinished = false;
char marker = 'X';
string message = "Starting script...";

Subsequent updates to declared variables use assignment statements without repeating the type: 

count = count + 1;
isFinished = true;

4. Expressions and Operators

Expressions are evaluated recursively. Operator precedence is fixed in the parser from lowest to highest:

Operators Description Associativity
|| Logical OR Left-to-right
&& Logical AND Left-to-right
==, != Equality comparisons Left-to-right
<, >, <=, >= Relational comparisons Left-to-right
+, - Addition, subtraction, and string concatenation Left-to-right
*, / Multiplication and division Left-to-right
!, - Logical NOT and unary negation Right-to-left
Division by Zero

The division operator (/) performs integer division. Division by an expression that evaluates to 0 is caught at runtime and aborts execution with a division by zero error.

5. Control Flow

C-Lite supports conditional statements and while loops. Statement blocks are enclosed in curly braces { }.

Conditional Statements

Conditionals are structured using if, optional else if, and optional else blocks. Parentheses around conditions are permitted but optional: 

if (value > 100) {
    echo "Value exceeds limit" endl;
} else if value > 50 {
    echo "Value is acceptable" endl;
} else {
    echo "Value is low" endl;
}

While Loops

Loops execute their body as long as the condition evaluates to a non-zero (or true) value: 

int i = 0;
while i < 3 {
    echo i;
    i = i + 1;
}

6. Scoping Rules

C-Lite implements lexical scoping using a stack-based symbol table.

  • Block Creation: Nested scopes are created inside curly braces { }. Variables declared inside a block belong to that local depth level.
  • Variable Shadowing: Variables in an inner block shadow variables in outer blocks sharing the same identifier name.
  • Cleanup on Exit: When execution exits a block, the scope depth decreases, and all variables declared at that depth are discarded from the stack.
int x = 10;
if true {
    int x = 20; // Shadows global x
    echo x; // Prints 20
}
echo x; // Prints 10 (global value is preserved)

7. Procedures (Functions)

C-Lite supports declaring and invoking user-defined subroutines. These function structures do not return values (there are no return statements implemented) and act as procedures.

Procedures are declared using an identifier name, parameter lists, and a body block: 

printSum(int valA, int valB) {
    int result = valA + valB;
    echo "Sum is: " + result endl;
}

printSum(12, 8); // Sum is: 20
Important Parameter Scoping Quirk

Function parameters are evaluated and inserted into the symbol table before the function body block is executed. Consequently, parameters are bound at the caller's scope depth level rather than the function's internal scope depth level.

This leads to two critical behaviors:

  • Re-declaration clash: If a parameter name matches a variable defined in the caller's environment, a "Redeclared in same scope!" error occurs.
  • Parameter leak: Parameters are not cleaned up when the function returns, remaining active in the caller's environment.

Best Practice: Always use unique parameter names (e.g., fn_arg_val) to prevent naming conflicts with calling scopes.

8. Implicit Type Conversions

The interpreter supports several implicit type coercions to simplify scripts:

  • String to Int: Assigning a string to an integer yields the length of the string: 
    string text = "Hello";
int size = text; // size is assigned 5
  • String to Char: Assigning a string to a character yields the first character of the string: 
    string text = "Hello";
char letter = text; // letter is assigned 'H'
  • Char to String (Concatenation): Summing two characters produces a two-character string: 
    char a = 'C';
char b = 'L';
string result = a + b; // result evaluates to "CL"
  • Mixed-Type Concatenation: Adding a string to any other primitive (int, bool, char) formats the primitive and concatenates them: 
    echo "The count is: " + 42 endl;
Coercion Limits (Interpreter Crash)

Implicitly converting non-string primitive values directly to a string variable (e.g., string s = 10;) is not supported and will result in a Segmentation Fault.

Workaround: To assign a primitive to a string variable, concatenate the primitive with an empty string: string s = "" + 10;.
