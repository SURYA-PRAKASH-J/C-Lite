C-Lite Programming Language

A complete reference guide, syntax walk-through, and execution model documentation handbook.

Introduction

C-Lite is a minimal, structured scripting language inspired by standard C syntax. It is implemented with a hand-written tokenizer, an Abstract Syntax Tree (AST) recursive-descent parser, and a tree-walking interpreter.

The language is designed to offer clean block scoping, explicit type definitions, standard operators, conditional execution, loops, and custom procedures. It prioritizes syntax transparency and predictable scoping rules.

Getting Started

To run C-Lite scripts, compile the interpreter using the Makefile in the repository root directory:

# Build the clite executable
make

# Execute a script (.cl file)
./clite examples/basics.cl

# Run with debug flags to dump tokenizer states and execution traces
./clite examples/basics.cl --debug

Variables & Data Types

C-Lite variables must be declared explicitly with their corresponding types. Variable updates use simple assignments.

Supported Types

Type Name Description Example Literal
int 32-bit signed integers 42, -10
bool Boolean state indicators true, false
char Single-byte character values 'A', 'z'
string or str Heap-allocated text sequences "Hello World"

Usage Example

// Declarations
int count = 10;
bool active = true;
char grade = 'A';
string greeting = "Hello C-Lite!";

// Assignments (do not repeat the type)
count = 25;
active = false;

Operators & Expressions

Expressions combine literals, variables, and operators. Evaluated expressions produce a typed runtime value.

Arithmetic Operators

  • + : Addition / Concatenation
  • - : Subtraction / Negation
  • * : Multiplication
  • / : Integer Division (aborts on division-by-zero)

Comparison & Logical Operators

  • Comparisons: ==, !=, <, >, <=, >=
  • Logical operations: && (AND), || (OR), ! (NOT)

Usage Example

int a = 20;
int b = 3;
int sum = a + b;           // 23
int division = a / b;      // 6 (integer division)
bool isGreater = a > b;    // true
bool matches = (a == 20) && !active;

Control Flow

Control flow structures use boolean expressions to determine which code blocks execute.

Conditionals (If-Else)

Conditionals can contain optional else if and else blocks. Parentheses around conditions are optional.

if score >= 90 {
    echo "Excellent!" endl;
} else if score >= 80 {
    echo "Very Good!" endl;
} else {
    echo "Keep practicing." endl;
}

Loops (While)

Iterates a statement block as long as the condition evaluates to non-zero (or true).

int idx = 1;
while idx <= 5 {
    echo "Count: " + idx endl;
    idx = idx + 1;
}
The `echo` & `endl` Statements

The echo instruction evaluates an expression and outputs it to the terminal. By appending the endl keyword, you append newlines. E.g., echo "Hello" endl endl; prints "Hello" followed by three newlines (since the initial echo already appends one newline by default).

Scoping & Shadowing

C-Lite enforces strict **lexical, block-level scoping** using a symbol stack table:

  • Block Creation: Every bracket pair { } increments the lexical scope depth.
  • Shadowing: Declarations in inner blocks shadow declarations in outer blocks if they share the same name.
  • Scope Exit: When a block ends, all variables declared within that block are popped off the symbol stack.
int val = 100;
echo "Outer val: " + val endl; // prints 100

if true {
    int val = 50; // Shadows outer 'val'
    int temp = 999;
    echo "Inner val: " + val endl; // prints 50
    echo "Inner temp: " + temp endl; // prints 999
}

echo "Outer val restored: " + val endl; // prints 100
// echo temp; // Compiler Error: 'temp' is out of scope!

Functions / Procedures

Functions allow reusable blocks of code. They behave as procedures (they cannot return values, and return statements are not implemented).

Function Definition & Invocation

Functions are defined using an identifier followed by parameters (with explicit types) and a code block. Return types are omitted.

// Declaration
calculateSum(int valA, int valB) {
    int sum = valA + valB;
    echo "The sum is: " + sum endl;
}

// Invocation
calculateSum(15, 30);
Critical Scoping Quirk for Function Parameters

Function arguments are evaluated and inserted into the symbol table before entering the function body block. As a result, they are bound at the **caller's depth level** (e.g., depth 0 if called from global scope).

  • Conflict Hazard: Calling a function with a parameter name that already exists in the caller's scope will trigger a Error: Redeclared in same scope! crash.
  • Parameter Leakage: Upon function exit, parameters are not cleared and remain active in the caller's scope.
  • Best Practice: Always name function parameters uniquely (e.g., prefixing them as fnParamVal) to avoid scope conflicts.

Type Coercion & Coercion Limits

C-Lite provides built-in implicit type coercions. However, because it is compiled under C-style structures, some conversion paths are illegal and crash the interpreter.

Working Implicit Conversions

  • String to Int: Returns the length of the string. 
    string s = "Antigravity";
int len = s; // len becomes 11
  • String to Char: Returns the first character of the string. 
    string s = "Hello";
char c = s; // c becomes 'H'
  • Char + Char Concatenation: Concatenating two characters yields a new 2-character string. 
    char c1 = 'X';
char c2 = 'Y';
string pair = c1 + c2; // pair becomes "XY"
  • Mixed-Type Concatenation: Adding string to primitives formats the primitive value automatically as text. 
    echo "Score: " + 100; // yields "Score: 100"
Forbidden Conversion (Interpreter Crash)

Assigning a primitive value directly to a string variable (e.g. string s = 10;) is not supported and causes a **Segmentation Fault**.

Workaround: Concatenate the primitive with an empty string: string s = "" + 10;. This handles the conversion safely.
